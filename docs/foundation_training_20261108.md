# 2026-11-08 基础能力强化与存储预算

本轮从第 2000 步 expand.best 继承权重，使用新优化器，计划独立训练 1500 步。上一轮日常对话试训降低了重复，但原 60 题从 23/60 降到 21/60，新推理也未改善；因此先从已有基础检查分数较高的父权重重新强化。这个小型对照不足以证明父模型全面更好。

## 课程与评测

总计 12000 条，含 11400 训练、600 内部验证；另留 600 条家族隔离样本。样本比例：推理/基础指令 50%、Python 代码 30%、日常对话 20%。

- 新生成推理覆盖小数字算术、数量变化、比较、时间/星期和确定性规则，并提供直接回答与一两步简解。核心数字域以 0–20 为主，不把所有小数字禁止后再把数字域差异误作泛化。
- 代码为 12 类已知行为的参数/边界变体，中英双语，含完整签名、返回值及边界案例；按独立 Python 参考与有界 AST 解释器核验，不执行模型生成代码。函数改名不算新能力。
- 少量回放从旧训练集选取复制、大小写、逆序、长度、排序和字段读取任务，重新计算答案并保留原家族标识；不复制整套旧语料。
- 日常聊天重用已筛选的现有候选，本轮实际选中的是中文对话。公共聊天仍是启发式筛选，未逐条完成事实核验。
- 所有生成参数家族绑定中英/直接/说明变体，内部验证和额外留出按家族分开。排除原 60/40 题、旧留出和新两组 64 题的原句及可识别参数家族，技能重叠与已有能力回放是有意设计。

新增开发集 64 题和不同固定参数种子的留出 64 题，各为 40 推理、24 代码，48 中文、16 英文。两组语义参数键无交叉；额外参数留出在本轮训练结束后才比较模型结果。它们属于同域参数诊断，不能称绝对盲测或通用智力基准。编程功能分数与“只输出代码”的格式遵循分别记录，不能互相替代。

实际文件哈希、语言/任务分布、9026 次代码参考用例、全部 10080 条含留出能力答案核验和 1024 个训练窗口检查见 [测量证据](foundation_training_measurements_20261108.json)。数据使用 `/root/uTTT/data/foundation_curriculum_20261108_v2/`，早期准备版本未用于训练。

## 训练设置

配置为 `configs/5090_foundation_20261108.yaml`：1.584B、BF16、序列 512、语义 B1/累积16；慢权重/W0 学习率保持 1e-5/5e-6，100 步预热。保留已有只读 GEMM 和步内合批，关闭编译与在线写入；Surprise 辅助为0，属于语言 SFT，未启动元训练或长期记忆写入。

原有 60 题质量门槛保持至少 50% 且不低于父模型。训练前后独立评估新的开发题，训练后再检查参数留出和对话保留情况。通过窄题集不表示自动部署；本轮无服务替换或自动元训练。

## 存储约束

仅做一组新模型，不下载新的大语料，不删除旧模型。新增语料及准备文件只是几十 MB。

本轮显式设置：

- `checkpoint_keep_previous: false`：本输出不长期保留 `.prev`。
- `checkpoint_full_on_validation_improvement: false`：非周期的验证改善只更新 best，不复制优化器。
- `checkpoint_save_initial_full: true`：首步建立可恢复状态；之后每500步、停止及最终保存完整状态。

最新完整状态约 15.44 GB，最佳模型约 6.34 GB，稳态新增约 **21.78 GB**。完整状态原子写入时需要临时文件，瞬时新增峰值约 **37.23 GB**。C 盘启动要求大于峰值加 **100 GB** 余量，D 盘至少留15 GB。旧目录不按本轮策略清理。

临时文件完成写入、同步并原子替换后才清理本输出的旧 `.prev`；失败时保留可读检查点。best 可能比 latest 步数更新，恢复权重、Adam、游标和随机状态仍取自 latest，只从经过身份核验的 best 继承选择分数。

存储测试覆盖写入/fsync/替换失败、同步流式与异步快照、best先成功但full失败、较旧latest恢复、dropout轨迹和验证期间停止。最终 CPU 回归共542项，520通过、22跳过；真实大模型保存还会在启动后核验。
