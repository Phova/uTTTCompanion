# 2026-11-06：修复条件指令训练并接入精确元训练

旧任务已于北京时间 2026-11-04 09:47 完成 100000 步预训练和 6000 步 SFT。最佳 SFT 在 5750 步，验证 CE 为 2.075995，但四项基础指令测试全部失败。较低 CE、生成 EOS 或较少字面重复均不能替代能力评测。

本轮保留旧权重，以新的独立任务继续训练 1,583,879,748 参数模型。代码、数据指纹、评测题目和恢复状态均绑定到该任务；不会覆盖旧实验。

## 已确认的缺陷及修复

1. **生成边界不符合实际 BPE 训练前缀。** 完整训练文本的答案首词可以编码为 `ĠHello`，单独编码提示末尾空格却得到独立的 `Ġ`。生成提示现在止于 `<|assistant|>`，由模型生成答案空白。相同 5750 步权重的无惩罚贪心对照中，`Hello` 从字典格式错误答案恢复为正常问候；四项计分任务仍为 0/4，不能据此声称模型已经合格。
2. **长 SFT 窗口经常丢失问题条件。** 对全文件固定种子抽取 10000 篇、每篇模拟三次旧裁剪，13670/30000 个窗口未保留第一个监督目标对应的完整用户轮次；其中 3524 个窗口完全没有用户角色。新策略保留所选问题、助手边界和答案开头，尽量保留近期完整历史，截断答案不补假 EOS。在同一批样本上，缺少完整问题的窗口为 0。`conditioned_turn_v1` 与序列长度进入 SFT 指纹，旧游标不能静默套用新策略。
3. **BF16 下的首次动态状态初始化失去精度。** 隐式可写状态原先跟随激活精度，首轮 W/S/LN 先被转换为 BF16。现在保留 FP32 主状态，检查首次读取与原始参数逐位一致。协议升级为 `chunk_shared_fp32_exact_v2`，旧元训练检查点必须显式转阶段；只读语言路径保留原精度策略。
4. **无未来监督的 writer 可能收到零梯度而被 AdamW 衰减。** 单块及只有首块受监督的序列回退到非重入重算，并直接从受监督首块构建 CE。公开完整 logits 和可微 Surprise 指标保留。回归要求这些 writer 的梯度为 `None`、没有 Adam 状态且权重不变。
5. **后续训练的生命周期。** 新流水线支持首次保存前中断重试、严格的完整状态恢复、已验证 `.prev` 回退和独立报告。恢复时不把 `.best.pt` 当完整检查点，不绕过可读但来源冲突的主文件；停止工具优先通知流水线，阻止其进入下一阶段。

## 与原论文的关系

对照 `.prompt/2610.05484v1.pdf` 第 2、3.1、3.4 节及附录 C、D，保留两个关键要求：各层读取当前块开始时的共享状态，当前块写入只影响后续块；任务 CE 必须经过可微写入反传到早先的读写参数和初始化状态。

项目继续采用 `MAIN-PROMPT.md` 指定的 Dense SwiGLU、MSE 重构和顺序写入。论文附录 C.2 讨论顺序调度，但主语言实验采用关联内损失、聚合写入、Muon 和行范数处理；本项目不声称复现了全部实验设置。直接将聚合更新替换进旧模型会改变内循环协议，需要另行训练和对照。

外层 `surprise_aux_loss_weight=0` 保持不变。元训练开启 `update_fast_weights=True`，CE 穿过完整更新链；真实 Surprise 仍单独测量。把辅助损失设为零与关闭写入是不同操作。

原论文 760M 语言实验使用 42.9B token、32768 上下文。本轮先前的语言准备阶段只有 3.2768B token、1024 序列，不能视为同预算复现，也不保证通过增加参数就获得相应能力。

## 数据与评测

- `data/instruction_recovery_20261105/train.jsonl`：36000 条保留原始来源/版权字段的公共指令，加 12000 条程序计算答案的中英短指令。公共样本按中英及来源文件配额选取，在各来源内部优先完整短样本；拒绝无效角色、空答案和重复题目。
- 同目录保留独立 1200 条合成留出样本，并按 10 个任务、两种语言抽取 60 条监控题。合成训练/留出集的语义键、问题、措辞、操作数和字符串载荷均隔离。公共语料中的普通数字不承诺没有语义重叠。这是基础指令监控，不是通用能力基准。
- `data/memory_20261106_768/`：2048 条训练、256 条留出，包含中英延迟检索和旧值纠正。实际 BPE 检查答案没有被裁掉、事实到答案距离超过 512 token、身份和新旧代码跨集合隔离，只有最终答案及真实 EOS 参与 CE。
- 记忆评估对同一留出文档分别从独立 FP32 W0/零动量开始，比较动态写入和冻结记忆的答案 CE 与教师强制 token 准确率。它不等于自由生成准确率；超过单层窗口也不能排除多层注意力传播，因此必须保留冻结对照。

## 元训练显存与验证范围

保留全部 1.584B 模型参数，元训练冻结 embedding、注意力和外部归一化参数，训练 944,727,108 个记忆相关参数。冻结只关闭参数梯度，仍保留穿过主干的梯度路径。

采用时间块与每 4 层分段重算；重入路径显式传递全部 W/S 和 KV 张量，支持标准 `loss.backward()`。需要 `autograd.grad` 或带 `inputs=` 的反向接口时应使用默认非重入策略。未使用状态 detach、低精度主状态或优化器量化。

`PYTORCH_ALLOC_CONF=expandable_segments:True` 在子进程导入 Torch 前设置，并在元训练阶段强制 28 GiB 分配上限及额外驱动余量。容量报告的模型、词表、参数范围、序列、块大小及重算策略必须与训练配置匹配。

1024 token 的独立两步容量测试通过，首次八项状态均为 FP32，204 个 writer 参数均收到非零 CE 梯度。但包含验证和保存的真实训练在第二步仍超过上限；每 6 层重算也未改善。正式配置因此采用 768 token，保持模型规模和精确梯度。该配置已通过三个完整容量步骤、包含验证与异步保存的三个真实训练步骤，并从完整检查点恢复到第 4 步；真实训练峰值 allocated 为 **26.89 GiB**。独立容量结果不再当作完整训练通过的证明。短程验证的动态 CE 仍略差于冻结 CE，不据此声称已经学会有用记忆。

CPU 全量回归为 **341 项：320 通过、21 项按平台/CUDA 条件跳过**。另有 **5 项 CUDA FP32/BF16 测试通过**，涵盖完整/记忆参数训练、首次 FP32 主状态、冻结主干梯度和逐参数重算对照。BF16 的分支累加存在舍入差异，逐元素限制为一个 BF16 epsilon 乘该参数梯度峰值，另限制每参数相对 L2；FP32 对零附近梯度使用明确的绝对噪声预算。测量细节见 [原始记录](training_recovery_measurements_20261106.json)。

## 独立训练流程

冻结源码位于 `/root/uTTT/runs/20261106_recovery/`，新任务 ID 为 `20261106_recovery`。计划为：

1. 对旧最佳 SFT 做固定提示边界下的 60 条留出监控评测。
2. 从旧最佳 SFT 初始化，以新数据训练 2000 步，输出 `checkpoints/uttt_1.584b_20261106_recovery.pt` 及 `.best.pt`。
3. 对新最佳权重使用相同留出题目评测；需正确率提高、至少 50%，且 EOS 比例未明显回退。未通过则记录 `quality_failed` 并保留权重，不自动开始元训练。
4. 通过后记录独立记忆基线，以 `parameter_scope=memory` 做 500 步元训练，保存 `checkpoints/uttt_1.584b_20261106_meta.pt`，再检查语言和动态/冻结记忆对照。

训练状态与每阶段日志在 `logs/recovery_20261106_recovery/`。状态区分 `training_complete`、`quality_passed` 和记忆诊断；流水线不会自动替换服务模型或授权在线写入。教师强制 CE 改善仍需自由生成和实际交互验收。

独立 Windows WSL 前台所有者持有训练，断开 SSH 不会依赖当前连接存活。正常停止仍使用 `remote_ctl.sh stop train`；恢复必须保留同一源码快照、配置、数据及评测哈希，并向 `deploy/run_recovery_training.py` 追加 `--resume`。
