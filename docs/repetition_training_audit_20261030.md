# 2026-10-30：预训练重复输出诊断

## 已确认与尚未确认

第 21500 步对应约 704,512,000 个名义训练 token。当前语言阶段参与梯度的参数为 1,137,973,760，因此约为 **0.62 token/活跃参数**；这是较早的预训练阶段。验证交叉熵此前持续下降，但这不代表生成质量已经合格，也不能单凭这一比例确定每次重复的成因。

当时运行的 `2680c84` 快照只输出固定的中英文科学前缀的贪婪续写。其惊奇度零值是关闭在线 TTT 写入的占位值；两者不能证明元训练崩溃。贪婪续写里的循环是明确的质量问题，但还需要随机采样和不同主题对照，才能区分解码集中于局部循环与更普遍的权重能力不足。

## 语料抽样结果

使用 `deploy/audit_corpus_repetition.py`，固定种子 42，从训练二进制语料不放回抽取 5000 个 1024-token 窗口。统计同一文档段内完全相同的 16-token 串第三次及以后出现时的末 token；遇到 BOS、EOS、角色或填充标记重新计数，保护文档边界。

- 有效监督目标 5,110,663 个，其中被该标准标记的目标 3384 个，约 **0.0662%**。
- 重复比例至少 5% 的窗口为 14/5000，至少 10% 的为 5/5000。
- 高重复样本包含学术表格标记、法规惯用措辞和分隔线，并不都应被当作坏数据删除。

这一抽样没有发现足以支持全面屏蔽重复目标的证据。本次保留标准交叉熵、现有训练语料、Adam 状态与学习率；不新增负向重复惩罚。该审计仅覆盖窗口内的长串重复，不能排除跨文档近重复或其他数据质量问题。原始二进制没有保存逐文档来源索引，报告提供可复查的 token 偏移和片段，不推测来源 URL。

## 已改善的训练诊断

1. 采样函数显式进入 `eval`，在成功或异常后都恢复原来的模式与重复惩罚配置，并保留 CPU/所用 CUDA 随机数状态。
2. 原始 greedy 与固定种子的随机采样都使用标准逐词解码，明确禁用推测解码和 CUDA Graph，重复惩罚固定为 1.0，以免隐藏待诊断的循环。结果记录实际控制参数。
3. 所有采样复用同一份只读快权重视图，不再逐条复制完整 W/S；AMP 读取缓存只在权重固定的诊断范围内复用，返回训练前退出。
4. 保留原科学主题的两个前缀，并增加中英文生活主题各一个，合计四个前缀、八条 greedy/sampled 对照。

这些修改改善观察可靠性及验证开销，不改变训练更新，也不能使已有权重立即停止重复。48-token 的文章续写尚未生成 EOS 通常不构成错误，不能套用聊天回答的停止标准判断预训练。

## 第21500步实际检查点对照

在同一个最佳检查点上，对4个中英文续写前缀各生成48 token，固定种子42起逐任务递增。评测明确不加聊天模板，原始结果不使用重复惩罚。原始统计见 [实测记录](repetition_profile_result_20261031.json)。

| 解码方式 | 平均token四元组重复比例 | 平均文本字符四元组重复比例 |
|---|---:|---:|
| 原始贪心 | 33.33% | 50.16% |
| 原始随机采样，temperature=0.8、top_p=0.95 | 2.22% | 10.72% |
| 另行标注的受控采样，penalty=1.05、禁止重复token四元组 | 0% | 6.49% |

这些结果支持贪心解码显著加重当前循环的判断。受控结果中的token四元组为零是解码约束直接造成的，不能当作训练治愈；文本仍可能语义重复、不通顺或不真实。4个短前缀也不能代表全面语言能力。

另对当前最大模型抽查中英文各8个位置的缓存逐词计算与完整前缀计算。管理器加载后明确关闭TF32，用相同的BF16加载再FP32上转权重比较；16个贪心token全部一致，最大绝对logit误差约6.20e-6。此检查未发现该范围内的缓存错误，不代表所有上下文长度和推理后端的证明。

正常停止流程现在将已请求的中断写为 `interrupted` 并简短退出，不再打印异常堆栈；非预期异常及不完整检查点仍报告失败，且不会启动后续SFT。

## 下一次判断标准

持续跟踪独立验证 CE，以及四个主题中 greedy 与 sampled 的重复指标和实际内容。若只有 greedy 明显循环，优先依据受控随机采样判断语言能力，同时保留原始 greedy 结果；若两种解码在多主题下都持续恶化，则进一步检查权重、词表与缓存一致性，并依据验证和实际任务效果调整训练预算。指令遵循在后续 SFT 后单独验收。
