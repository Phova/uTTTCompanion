# 2026-11-07：短指令 SFT 执行提速

新增可选的步内合并执行，保持原有 B1 采样、每步 16 条样本、每样本平均 CE、优化器更新次数和数据切分。旧配置默认保持原执行路径；本优化只接受关闭动态写入、dropout=0、未编译的 SFT。

## 执行方式

先按原顺序物化当前优化器步的 16 个样本，逐条推进原 B1 数据游标，然后仅在这 16 条内按有效长度稳定排序，最多合并 4 条执行前后向。跨 epoch 的尾部仍逐条消费，不丢样本，不进行整轮分桶，也不把独立对话拼接到同一行。

PAD 从 128 桶改为 32 桶。输入、标签和掩码共同裁剪/补齐，保留有效内容和真实 EOS。执行组的物理 token 预算为 1536；超过时折半组大小，长样本自动使用 B2。实际 OOM 时优先缩小执行组，清梯度并恢复本步起点的游标、随机状态和 loader，完整重放本步。

模型新增显式 `ce_reduction="sequence_mean"`：每行先按该行监督目标数归一化，再按行平均；组损失乘以本组样本数/本步样本数。直接将原 token 平均 CE 用于较大微批，会改变长短答案的权重，因此没有采用。默认 `token_mean` 路径保留，动态写入不能使用此选项。

## 完整模型测量

RTX 5090，1,583,879,748 参数，FP32 参数/梯度和完整 fused AdamW 状态，BF16 AMP；同一 12 条程序指令 + 4 条公共指令，1306 有效 token。预热 1 步、测量 5 步；学习率为 0，不改写正式模型权重。

| 执行方式 | 秒/优化器步 | 有效 token/s | 峰值 allocated |
|---|---:|---:|---:|
| 原 B1、PAD128 | 1.109 | 1178 | 23.47 GiB |
| 最多 B4、PAD128、步内排序与预算 | 0.704 | 1856 | 27.06 GiB |
| 最多 B4、PAD32、步内排序与预算 | **0.610** | **2143** | **25.70 GiB** |

另一次同样本原 B1 测量为 1.025 秒，未加预算的 B4/PAD32 为 0.609 秒。整体说明这批样本约有 **1.7–1.8 倍**收益，不代表所有数据长度或整轮训练都得到同样倍数。16 条实际长度 480–510 的样本，带预算的最终配置自动缩为 B2，峰值 **25.05 GiB**，无 OOM；未经预算限制的 B4 会 OOM，不能作为发布设置。

数学目标与 FP64 CPU 梯度等价测试一致。BF16 分组和矩阵形状会改变舍入，不能保证逐位相同；本批全参数裁剪后梯度的相对 L2 差约 3.42%，余弦相似度约 0.99942，loss 变化约 0.0000844。这里验证的是执行目标和数值行为，不是泛化质量改善。

还使用真实 `train()`，从同一第 6000 步的完整状态、游标和 RNG 各执行 30 步，包含分词、物化、组批和固定内存传输。稳定的同一区间原路径为 **1384 有效 token/s**，新路径为 **2206 有效 token/s**，约快 **59%**；新路径峰值为 **27.06 GiB**。测试使用独立检查点副本、关闭导出和质量验证，RAM 内训练结果未保存为正式模型；正式检查点 inode、大小和修改时间保持不变。这是短程性能测量，尚无新执行配置的整轮质量验收。

## 配置与验收

独立配置为 `configs/5090_advance_fast_20261106.yaml`，新增：

```yaml
training:
  sft_execution_batch_size: 4
  sft_padding_multiple: 32
  sft_sort_by_length: true
  sft_max_group_tokens: 1536
```

配置保留语义 `micro_batch_size: 1`、`grad_accum_steps: 16`，并使用独立 `advance_fast.pt` 输出。已完成运行的冻结源码、配置和正式权重均保留。流水线对配置/版本的原绑定检查未放宽；不能把新配置冒充原运行继续。

CPU 全量回归 **413 项：391 通过、22 跳过**。新增测试覆盖 B1/B2/B4 的所有参数梯度、长短答案权重、真实 EOS、所有样本保留、尾组、跨 epoch、随机窗口恢复、物化时 OOM、部分反传后 OOM、实际两步 Adam 训练及检查点游标。

此前 6000 步正式 SFT 已完成，训练损失约 0.34，而验证 CE 升至 2.1275，固定监控正确率仍为 14/60，EOS 为 100%。这表明训练拟合改善尚未转化为该监控集上的指令泛化。此次执行提速不作为质量通过或在线记忆验收依据，也未自动追加正式训练。

原始 GPU 数值及真实训练器测量记录见 `sft_execution_measurements_20261107.json`。
