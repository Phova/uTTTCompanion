# 共享 W0 计算与可选回复词表投影

本轮实现两项默认关闭的 SFT 计算选项，并将推理投影合并与内核编译解耦。此前的步内合并、PAD32、CUDA Graph、KV 缓存和流式解码优化继续保留。

## 计算范围

`training.sft_shared_readonly_gemm=true` 只对模型内部 `readonly_state()` 创建的共享 W0 使用展平二维 GEMM，替代展开批次后的 BMM。全部样本仍有独立激活，W0 继续接受外层梯度。动态快权重、不同用户状态、持久化状态及复制后的状态保留普通 BMM；检查点重算重建状态时也安全回退。

`training.sft_loss_only_head=true` 在 CPU 上预先选择所有 `labels[:, 1:] != -100` 的位置，只对相应隐藏状态计算最终归一化、词表投影及 CE。Transformer 仍读取完整提示词，提示词梯度、真实 EOS、各样本 CE 权重和优化器更新次数均保留。公开默认前向仍返回原有 logits；显式传入 `ce_token_indices` 的调用为仅损失模式，返回空 logits。该低层索引参数须由 `supervised_token_indices(labels_cpu)` 生成，不支持任意省略监督目标。

两项训练配置只接受 `stage=sft`、`torch_compile=false`，并记录到导出指标中。旧配置默认关闭，已完成训练的冻结源码及正式权重保持原记录。

## 测量方法

RTX 5090、1.584B 模型、PyTorch 2.11.0+cu128，FP32 参数/梯度/完整 Adam，BF16 AMP。只读载入追加阶段第 6000 步完整检查点；每种配置独立进程，从相同模型和 Adam 状态开始。固定同一组 16 条真实训练样本、同一 PAD32/排序/1536 token 上限执行计划，预热 2 步，测量 8 步。

每步包含固定内存传输、前后向、梯度裁剪和 fused Adam。数据解析及首次物化、验证、模型保存和冷启动载入时间不计入稳定计算吞吐。计数使用非 PAD 的有效 token；这不是整轮训练时长测量。

该批每步 2424 个有效 token、3520 个物理 token、2047 个监督目标；四组计划摘要均为 `76da481f90382b9da60041f687dada86b1fef08a65aed7ae8369443fa92a7ed9`。

| 设置 | 秒/步 | 有效 token/s | 峰值 allocated |
|---|---:|---:|---:|
| 现有执行路径 | 0.788 | 3077 | 26.15 GiB |
| 仅回复词表投影 | 0.788 | 3076 | 26.15 GiB |
| 仅共享 W0 GEMM | **0.710** | **3416** | 26.16 GiB |
| 两项同时启用 | 0.711 | 3410 | 26.16 GiB |

共享 W0 的该批稳定吞吐提高约 **11.0%**，显存峰值没有明显下降。回复占有效 token 的约 84%，筛选投影没有可测的额外速度收益，因此推荐当前这类混合 SFT 使用共享 GEMM、保留原词表投影。筛选投影仍可用于回复很短的工作负载，但尚未实测该场景，不能承诺收益。

新训练阶段可显式配置：

```yaml
training:
  sft_shared_readonly_gemm: true
  sft_loss_only_head: false
```

这些数字来自固定批次的短程测量；BF16 舍入及 Adam 轨迹不保证逐位一致，也没有证明整轮质量提升。正式训练恢复仍须通过原有数据/版本/阶段绑定，不应热改冻结运行。

## 数值验证

完整 FP64/FP32 目标和参数梯度测试保留严格误差检查。BF16 BMM 先舍入每个样本的权重梯度再加总，共享 GEMM 对 B×T 一次归约，不能保证逐位相同。BF16 测试同时对照同一 FP64 参考，限制两条路径的归一化误差及新增误差；测试也覆盖提示词梯度、不同回复长度、全忽略标签、真实 EOS、训练恢复和用户隔离。

最终完整 CPU 回归 469 项：447 通过、22 跳过；重点 GPU 回归 27 项全部通过，包含 B1/B2/B4 的梯度、BF16 参考精度、CUDA Graph 失效与用户状态隔离，以及短提示词、窗口边界和 window=1 的缓存内容/存储检查。原始测量和测试汇总见 [sft_compute_measurements_20261107.json](sft_compute_measurements_20261107.json)。

## 推理开关

`UTTT_PACKED_PROJECTIONS=1` 可在不启用内核编译的情况下使用合并投影；`0` 显式关闭。`personalizer.warmup(..., packed_projections=...)` 的显式参数优先于环境变量。未配置时保留原行为：编译预热启用合并，普通预热保留已有设置。布局或投影地址变化会丢弃旧 CUDA Graph，相同设置重复预热保留图。

远程服务也可显式选择：`./deploy/remote_ctl.sh serve --packed-projections --user-id Phova`；使用 `--no-packed-projections` 关闭。两个参数互斥，省略则沿用上述默认值和环境配置。

该开关用于服务启动和串行预热，不应与正在生成的请求并发切换。合并投影额外占用显存；关闭后已有用户的读取缓存可能保留至用户状态被淘汰。不会把已有 CUDA Graph 的历史收益再次计算为本轮收益。

同一第 6000 步 best 权重、128 token 固定提示词及 128 次解码，预热 1 次、测量 5 次：

| 推理路径 | 解码中位数 | 峰值 allocated |
|---|---:|---:|
| 普通投影 + CUDA Graph | 122.75 token/s | 3.305 GiB |
| 合并投影 + CUDA Graph + 紧凑 KV | **127.62 token/s** | 3.994 GiB |

合并路径提高约 **4.0%**，额外占用约 **0.69 GiB**；仍为可选设置。计时只包含模型和设备端贪心选词，不包含网络、文本解码及首次抓图；固定长度测量忽略 EOS，不能用其生成文本判断正常会话质量。

实测还发现并修复短提示词的 V 缓存保留完整 QKV 投影的问题。该 128 token 提示词在 34 层保留的 KV backing 从 38,993,920 降至 11,141,120 字节，等于所需的逻辑大小；全部缓存占用从 3.5 倍降至 1 倍。另修复普通增量解码跨窗口时先拼接再切片导致保留额外 token backing 的问题。两项均保持注意力数值和完整训练路径，默认 CUDA Graph 的环形缓存继续使用原实现。

## 后续空间及限制

当前只有一个解码图缓存；不同用户轮换可能重复抓图。受限的用户图缓存和连续批处理需要同时处理显存预算、用户淘汰和动态权重版本，尚未实施。

验证改善时仍同步保存 full 与 best。拆分频率前须处理恢复协调：完整检查点的历史最优分数必须与实际持久化的 best 文件一致。当前 full 先于 best 提交，跨文件失败存在配对缺口；直接减少 full 保存会进一步放大这个问题。本轮保留保存行为，不能据此宣称已缩短保存等待。

追加训练已完成到全局 6000 步；固定 60 题监控由 23/60 变为 24/60，仍低于 50% 的质量门槛。计算提速通过不代表模型质量或在线记忆验收通过。
