# 2026-11-06：推进基础指令训练

本轮从恢复训练的最终第 2000 步权重继续训练同一 **1,583,879,748 参数**模型。采用独立数据、配置、优化器和输出，保留此前全部正式模型。新阶段先推进语言 SFT；记忆元训练须在语言能力过线并检查容量后单独启动。

## 已核实的结果与原因

最终 2000 步权重在原有 60 条监控题上，无重复惩罚的贪心解码为 **14/60**，EOS 比例 **96.67%**。此前流水线评测的 `recovery.best.pt` 实际停留在第 1 步，只有 **2/60**。最低内部验证 CE 与基础指令正确率并不一致：第 1 步 CE 为 1.672536，最终为 1.693775，因而 best 一直未更新。

最终模型已能完成 6/6 JSON 提取、3/6 排序，以及部分大小写转换和复制；加减乘、字符计数和反转仍未通过本组监控题。英语任务中还出现了把复制或计数理解为反转的问题。

旧程序语料每种任务、每种语言只有一种训练措辞。2000 步实际训练接触 8123 个程序案例，每类约 800 个，不足一轮。公共长答案占据大多数验证目标 token；训练按微批样本平均 CE，验证却按目标 token 加权，因此公共长答案的损失主导了 best 选择。公共样本筛选还曾复用验证划分的哈希：名义 2% 的内部留出实际达到约 4%。

参数抽查确认模型确实更新，不能将未通过旧门槛归因于优化器没有工作。上述 14/60 是窄监控集结果，不代表通用聊天、翻译或在线记忆能力已合格。

## 新数据与隔离

`data/instruction_advance_20261106/` 共 **48000 条**：

- **36000 条程序指令**：原 12000 个训练参数案例各保留原措辞，并加入两种新训练措辞。每类任务、每种语言另有六种训练措辞池，覆盖复制、大小写、反转、计数、排序、提取及算术；答案重新计算验证。
- **12000 条完整短公共指令**：保留来源和版权元数据，整个对话的真实 BPE 长度必须不超过 512。可用完整英语样本为 4115 条，其余 7885 条为中文；全数据中英比例约 46/54。
- 原 **1200 条留出集**和 **60 条监控题**逐字节保留。未使用其参数、载荷或原措辞生成训练例，未降低验收门槛。

三种改写共用语义组 ID，公共样本按用户问题序列分组。训练器启用 `validation_group_key: validation_group_id`，使用独立哈希域划分内部验证，避免同一题的改写跨训练/验证。新文件实际划为 **47038 条训练、962 条验证**，语义组交集为 0。分组字段、策略和组身份进入数据指纹；默认关闭时保留旧协议行为。

全数据 BPE 保守平均长度 **90.27**，最大 512；按 128 桶向上补齐后平均物理长度约 **176.43**。抽查 1024 个训练/验证窗口，监督目标和真实 EOS 均保留。

## 训练与速度

配置为 `configs/5090_advance_20261106.yaml`：

- 从 `uttt_1.584b_20261106_recovery.pt` 的最终 2000 步权重初始化，新优化器训练 **6000 步**，约两轮新训练数据。
- 微批 1、梯度累积 16，最大序列 512；学习率为慢权重 **5e-5**、W0 **2.5e-5**，预热 200 步，权重衰减 0.01。
- BF16 激活与 FP32 参数、梯度及 Adam 状态，28 GiB 分配上限；不启用模型编译。
- SFT 关闭动态写入和外层 Surprise 辅助项，元训练内循环数学、协议及可微梯度未修改。

新增 `trim_sft_padding: true`：仅在 SFT、dropout=0、未编译时，CPU 端按每批最长有效前缀向上取整至 128 的倍数，裁剪公共右侧 PAD，再固定内存并传输。输入、标签和掩码同步裁剪，保留真实 EOS 和下一 token 目标；新执行标志也进入恢复检查。此优化不用于预训练或动态元训练。

同一批 **12 条程序任务 + 4 条公共指令**、同一 1.584B 模型、完整 FP32 AdamW 状态、BF16 AMP 测量如下。优化器学习率为 0，仅测执行成本，不保存或改写正式权重；各方案预热 1 步、测量 3 步。

| 执行方式 | 秒/优化器步 | 峰值 allocated |
|---|---:|---:|
| 固定 1024 | 2.220 | 25.01 GiB |
| 固定 512 | 1.370 | 23.49 GiB |
| 512 上限、128 桶裁剪 | **0.957** | **23.47 GiB** |

在这批相同有效 token/目标上，裁剪比固定 1024 快 **2.32 倍**，比固定 512 快 **1.43 倍**。这是受控样本测量；正式训练还包含不同长度、验证和保存，不能直接将该倍数当整轮耗时承诺。预计本阶段约两小时，以实际日志为准。

## 候选选择与运行

新配置显式启用 `recovery.evaluate_final_checkpoint: true`。训练结束固定评测最低 CE 与最终权重两个候选，先考虑通过全部正确率、改进及 EOS 保护的候选，再按正确率选择，同分优先最低 CE。未达门槛的安全改进可保留为中间模型，但不能启动元训练。报告、权重哈希、步数与版本随状态绑定，恢复时复用并校验，不反复重新抽选。

这两项属于固定监控集的模型选择，不是独立测试，也不用于反向传播。门槛仍为至少 50% 正确率、优于基线，并保持 EOS；不自动替换服务模型或开启在线写入。

本轮只启动 6000 步语言阶段，以保留 D 盘余量；通过后再单独验收记忆训练。输出为 `checkpoints/uttt_1.584b_20261106_advance.pt` 及 `.best.pt`，日志与状态为 `logs/recovery_20261106_advance/`，冻结源码位于 `runs/20261106_advance/`。Linux 路径仍在已迁移至 D 盘的 Ubuntu 内。
