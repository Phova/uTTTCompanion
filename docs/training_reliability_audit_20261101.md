# 2026-11-01：训练恢复、验证开销与内存审计

本轮基线为 `fd78f37`。检查范围是训练器、数据游标、AMP 生命周期和异步检查点；未停止正式训练、重置优化器、更换语料或改变 CE 目标。

## 已修复

**权重文件不能冒充完整恢复文件。** 原恢复分支在没有 `optimizer_state` 时仍沿用检查点的全局步数，实际 AdamW 却从零开始。`.best.pt` 正是权重文件，因此这个路径可以由正常项目输出触发。现在恢复前要求完整 AdamW 状态，并检查参数组对应关系、已有动量张量形状及每个已有状态的标量步数；需要重新初始化优化器时使用 `--init-from` 和新的输出路径。语言阶段没有梯度的 writer 参数可以继续没有 Adam 状态，不要求人为创建零状态，也不要求所有参数的 Adam 步数相等。

**语言验证不再创建无用可变人格状态。** CE 验证不使用输出状态，现在显式请求 `return_fast_state=False`，冻结语言路径整轮复用一份只读权重视图，省掉三组 W 克隆、三组动量分配及逐样本精度转换。整个验证轮次在同一 AMP 上下文中执行，在固定权重下复用转换缓存；离开上下文后才恢复训练模式。完整元训练验证仍从各样本自己的可变状态开始，冻结对照仍独立执行，损失和有效标签计数保持不变。

**吞吐计数与实际消费一致。** 日志使用当前区间真正消费的非 padding token 数，不再假设每批都有配置的 batch size 和完整长度；不足一个配置 batch 的小语料和短 SFT 数据不会夸大吞吐。当前全长预训练的计数不变。该速度仍为包含区间内验证、检查点等开销的墙钟速度，不能把维护附近的下降解释为纯训练内核退化。

**聊天诊断保留助手角色边界。** SFT/meta 生成样本使用统一的 `encode_chat_prompt` 预算逻辑，过长用户输入保留正文尾部和助手后缀。预训练原始续写路径保持原样。模板预算不足时明确报错。

## 性能机会与边界

34 层的 `w_k/w_v/k_norm/w_eta/w_alpha` 在语言阶段不执行，共 **445,905,988** 参数，FP32 常驻约 **1.66113 GiB**。这些参数未来可以仅在 pretrain/SFT 阶段有条件地保留在 CPU，同时保留参数注册顺序和检查点键。恢复、已有梯度/Adam 状态、整体 `.to()` 操作和切换 meta 阶段都必须处理，不能单独移动模块就默认生产启用。

历史 batch2、无重算测量为 **31.57 GiB reserved**；仅扣除 writer 的理论大小仍约 **29.91 GiB**，超过 28 GiB 目标。分配器、AMP 和注意力工作区还会影响峰值，因此当前证据不足以保证 batch2 更快或满足预算，正式训练继续采用已测稳定的 batch1/accumulation32。

共享 `W_up/W_gate` 可以在一次 forward 内尝试拼接、跨层复用读取。训练中的拼接必须保留 autograd，不能跨微批缓存其图，也不能跨优化器更新保存转换结果。BF16 拼接额外约 67.5 MiB，并会改变 GEMM 形状；需验证梯度、多步 AdamW 轨迹及真实吞吐后再决定。现有只用于推理的无梯度打包缓存不能直接当作训练缓存。

## 验证范围

新增 `tests/test_training_resume_validation_audit.py`，覆盖稀疏合法 Adam 状态、损坏恢复拒绝且保留原文件、真实小批和 padding 计时、FP32/BF16 的冻结与元训练验证对照、模式和 AMP 异常恢复，以及长聊天诊断模板保留。远端完整 CPU 回归248项中232项通过、16项平台/CUDA跳过；另12项CUDA图/缓存回归通过，最终BF16验证CE与旧路径一致。CPU小模型最终验证耗时25.52→23.33ms（约减少8.6%），仅代表该验证/主机开销实验，详见[原始记录](audit_measurements_20261101.json)。没有加载第二个正式模型，也没有据这些修改声称大模型稳定训练吞吐已经提高。
