吞吐中位数取 step > 100 且非 250 的整数倍的日志区间；训练耗时包含保存开销，二者口径不同。本轮没有相同数据上的速度 A/B，不能据此声称新的速度优化倍数。

两轮均采用基础推理/代码/聊天 **50/30/20 的样本配比**，每轮 11400 条训练、600 条内部验证，另有 600 条家族留出。比例按样本计，不代表 token 比例。能力数据为中英双语，聊天保留中文；答案经过独立参考计算和有界代码解释器核验，聊天文本未获得全面人工质量认证。

首轮继承 expand.best 第 2000 步权重，源码 `49457f6eefb4c6622d18644bee86dc4e47335184`；校正轮继承首轮第 1500 步 best，源码 `4d826dbbbd8f8b5d1ed513e0a1631fed28fc08d6`。两轮均使用新 Adam、BF16、序列 512、微批 1/累积 16、慢权重学习率 1e-5/W0 5e-6，以及既有只读 GEMM 和执行合批。最终完整状态已核对 Adam step、数据游标、RNG、源码及数据指纹，父模型完整哈希未变。

课程校正修复了三个明确问题：比较题规范参数总是升序且呈现未打乱；同一代码行为总使用固定函数名；有限的小算术案例被大量时钟/参数家族稀释。现在比较呈现升序/降序为 749/757，代码使用 8 种名称，并在原类别和分组配额内优先保留基础案例。默认无优先级的旧选择结果有 SHA 回归检查。修正和数据核验细节见 [校正说明](foundation_corrected_20261109.md) 与 [准备证据](foundation_corrected_measurements_20261109.json)。

校正内部验证可能包含父模型见过的其他呈现家族，CE 下降不能作为新的泛化证据。课程代码共 12 种简单行为，限幅、仿射与区间判断的参数案例占比较高；不是 12 种通用算法能力都得到同等训练。

原 60 题门槛仍要求至少 30/60 且不低于相应父模型；两轮均未通过。每轮 best/final 的开发集答复相同、旧 60 题得分相同。校正候选在状态中标为 `intermediate_only`，表示监控集未回退的中间候选，**不是部署或元训练许可**。

原 60 题生成上限 64 token，其余上述诊断为 128 token；统一无重复惩罚 greedy、无在线写入。聊天历史使用已修复 EOS 后换行的相同评估源码，三模型可比。不要混用此前历史边界有缺陷的原始聊天指标。

开发集已用于课程诊断。另 64 道参数留出在两阶段方案确定后才统一查询；两个最终课程文件与其规范参数家族交集均为 0，并记录文件 SHA。它们只测同域新参数，不能证明新技能、所有既往训练数据无泄漏或一般智力。12 道聊天题早已用于监测，也不是独立盲测。后续若继续依据这些结果优化，应另建最终评估集。

## 逐题核读

参数留出的主要增益集中在三数最值 0→4→4/4、乘法 0→3→3/4；校正阶段加法和星期仍各为 0/4。仍有 `6×7=49`、`40÷4=8`、`max(12,13)=21`。开发集校正轮新增答对数量和时钟案例，也把 `20−20` 从 0 改错为 10，不能认定一般算术已掌握。

两组新诊断中，通过代码都集中于限幅函数。参数留出首轮通过 `[-4,8]`、`[-1,6]` 两题，校正仅保留后一题；每题均 5/5 用例通过且只有代码。其他失分包括全角冒号破坏函数头、`def` 后缺空格、只有表达式而缺完整函数、函数名不符合接口，以及把前缀写成后缀。未发现明显评估器误判。功能解释器只支持有界纯函数子集，合法但不支持的 Python 也会失败，成绩不等同于标准编程基准。

聊天更容易结束且总体重复减少，但内容仍常常空泛。新小区题能自然邀请交谈，休息题给出散步建议；反例包括煎蛋题杜撰“蛋黄变质”、用户只想倾听时继续提解决方案、要求两个问题却没有给足。历史明确周末加班仍建议周末喝咖啡，两次强调不吃辣椒仍推荐辣椒菜，英文活动题仍把 `concert suit` 误当衣服。EOS 和重复率不是聊天质量分，也不能证明长期快权重记忆。

## 储存与恢复

- 每轮只保留 latest 完整状态约 **15.442 GB** 和 best 权重约 **6.338 GB**，常驻合计 **21.780 GB**。完整状态在首步、每 500 步、停止或最终保存；其他验证改善只更新 best。实际保存事件与策略一致，两轮均没有新增 `.prev`。
- 单个输出目录原子写入峰值约 **37.223 GB**，而非常驻文件的双倍。预算不含其他运行、数据、日志、缓存和系统占用；外部进程长期打开旧文件也可能延迟空间回收。
- 核验完整状态、哈希和任务/进程引用后，仅清理旧 chat 第 750 步的两份 `.prev`，回收 **21,780,368,104 字节**。旧 chat 第 1000 步 latest/best、原模型和首轮父模型均保留。两轮新增模型文件扣除此清理后净增 **21,780,368,360 字节，约 21.78 GB**。
- 最终归档时训练机 C 盘约 **136.8 GB**、D 盘约 **25.7 GB** 可用。规划余量为 C 100 GB/D 15 GB；这是本次监测和容量预算，训练器没有自动磁盘硬阈值。
- 关闭 `.prev` 的代价是每轮只有一个完整恢复点。硬中断最多回退到最近完整保存；best 不含 Adam、数据游标和 RNG。best 比 latest 新时，仅经严格同源核验合并其选择分数，训练仍从 latest 的完整状态恢复。

两组模型位于训练机 `C:\uTTT-artifacts\checkpoints\20261108_foundation` 与 `20261109_foundation_corrected`，未额外复制权重用于对照。不可变训练源码和全部原始报告保留在对应 runs/logs 中。结果发布仅更新报告，不修改运行状态和检查点。

## 后续优先级

完整 CPU 回归为 **550 项，528 通过、22 跳过、0 失败**。本次修复了课程偏差并降低检查点开销，但没有解决整体回答可靠性。

后续应优先按具体算术操作和代码行为分配配额，补齐加法、星期、完整函数语法/接口，以及不同语境下的相同规则；同时保留文本复制/大小写等旧能力回放。聊天课程需要加强角色归属、数量限制、明确禁用条件和历史纠正，并逐条核验。候选选择应联合基础题、代码功能和人工聊天核读，不能只按内部 CE。Surprise/在线写入仍关闭，本轮属于语言与指令基础准备，尚未建立 uTTT 在线适应能力。
